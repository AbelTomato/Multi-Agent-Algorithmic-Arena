## 遇到的问题

- Go 官方下载 TLS 连接失败；改由用户从镜像下载并以官方元数据 SHA-256 和文件大小校验后安装。
- 完整集成套件超过执行通道 30 秒上限；改为生命周期、隔离资源、并发/取消/OOM 三组运行，避免中断控制器清理。
- 阶段 2 原型把 `docker_error`/未知结果误归为 `RE`，并以固定期望下标比较 Two Sum；同步客户端还允许调用方任务 ID，且吞并控制器 HTTP 错误，无法供后续 API 映射。
- 在执行通道内直接以后台 shell 启动 `go run` 或临时二进制会被外层 30 秒通道回收；未创建候选容器或产生残留。

## 解决方式

- Go 仅使用标准库和项目内固定版本工具链，未引入第三方依赖。
- Docker Desktop 启动后先复核 daemon、cgroup 和固定镜像，再在获得“创建并删除带固定 Arena 标签的临时容器”授权后执行真实验收；对通道超时残留容器仅在双标签与任务 ID 匹配后进行针对性删除。
- 以失败测试先行：严格 schema 阻止未知字段/空或超量用例；Judge 按输入语义判定 Two Sum；控制器结果仅在可靠 OOM 证据时映射 MLE，Docker/未知执行结果映射 UKE；`409`、连接、超时、5xx 和畸形响应保留结构化异常给 API 层。
- 使用 `setsid nohup` 显式脱离执行通道后启动仅绑定 loopback 的已构建控制器；测试结束后发送 `SIGTERM` 并复核端口与 Arena 标签容器为空。
