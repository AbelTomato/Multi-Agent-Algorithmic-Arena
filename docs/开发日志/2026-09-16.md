### 遇到的问题

1. **Docker 权限问题**
   - 现象：`permission denied while trying to connect to the docker API`
   - 原因：用户已加入 docker 组，但当前 shell 会话没有激活组权限

2. **`sg docker -c` 命令解析问题**
   - 第一次尝试：`sg docker -c " ".join(docker_cmd)` → shell 解析括号失败，退出码 2
   - 第二次尝试：`sg docker docker run ...` → `sg` 把 `--rm` 当作自己的参数
   - 最终方案：使用 `shlex.quote()` 安全地引用每个参数

3. **Python 系统包管理限制**
   - 现象：`error: externally-managed-environment`
   - 解决：创建虚拟环境 `.venv`

### 解决方式

1. **Docker 权限问题**
   ```bash
   # 将用户添加到 docker 组
   sudo usermod -aG docker $USER

   # 在每次 Docker 调用时使用 sg docker
   sg docker -c '<docker command>'
   ```

2. **命令解析问题**
   ```python
   import shlex

   # 安全地引用每个参数
   docker_cmd_str = " ".join(shlex.quote(arg) for arg in docker_cmd)
   docker_cmd = ["sg", "docker", "-c", docker_cmd_str]
   ```

3. **虚拟环境**
   ```bash
   python3 -m venv .venv
   .venv/bin/pip install <packages>
   .venv/bin/pytest tests/
   ```

### 学到的东西

1. **`sg` 命令的正确用法**
   - `sg <group> -c '<command>'` 形式需要完整的 shell 命令字符串
   - 不能直接传递参数数组，会被误认为 sg 的参数

2. **Python `shlex.quote()` 的重要性**
   - 自动处理特殊字符、空格、引号
   - 防止命令注入攻击
   - 在构建 shell 命令字符串时必须使用

3. **Docker 安全参数组合**
   - `--network none`: 禁用网络
   - `--read-only + --tmpfs /tmp`: 只读根 + 可写临时区
   - `--user nobody + --cap-drop ALL`: 非特权用户
   - `--rm`: 自动清理容器

4. **pytest 集成测试的环境控制**
   - 使用环境变量启用/禁用集成测试
   - `@pytest.mark.skipif` 根据环境条件跳过测试

5. **TDD 流程的实际应用**
   - 先写基本测试 → 实现 → 集成测试 → 验证

#### 业务行为变化

1. **新增评测能力**：系统现在可以：
   - 加载版本化评测用例（按 slug 和 version）
   - 执行严格的 JSON 输出协议校验
   - 进行可信的语义判定（AC/WA/RE/TLE/OLE/UKE）
   - fail-fast 行为（遇到首个失败即停止）

2. **隐藏用例保护**：
   - 隐藏用例及期望值只在 Judge 内部使用
   - 不通过 API 返回
   - 不发送给执行控制器
   - 不写入常规日志

3. **严格判定规则**：
   - Valid Parentheses：拒绝 1/0/字符串代替布尔值
   - Two Sum：拒绝布尔值作为整数下标
   - 缺少字段/额外字段/类型错误均归类为 RE

#### 已知风险与限制

1. **集成测试环境依赖**：需要 Sandbox 执行控制器和 Docker 环境完全配置
2. **MLE 判定未完全实现**：只有状态枚举，缺少 OOM 证据检测逻辑
3. **仅支持两道题**：Valid Parentheses 和 Two Sum
4. **依赖 Sandbox 服务**：Judge 模块需要 Sandbox 执行控制器可用

#### 测试缺口

1. **集成测试未完全验证**：因环境配置问题，真实执行链路未完全测试
2. **并发测试缺失**：未测试并发评测场景
3. **TLE/OLE 测试缺失**：未测试超时和输出超限的真实触发
4. **MLE 测试缺失**：未实现 OOM 证据检测
