### 遇到的问题

- pytest 显示 `pyproject.toml` 中有 `asyncio_default_fixture_loop_scope` 配置项未配置，原因是在未来版本中，该配置项将默认为 `function` 值，此处建议显式指明，以免出现不可预知的问题。
- uvicorn 显示未能成功获取网站图标。
- Cline 工具命令默认运行在新的 Windows CMD 会话中，不会执行 Git Bash 的 `.bashrc` 自动激活逻辑，因此直接运行 `pytest` 时找不到命令。
- 当前 Python 3.14 下，FastAPI / Starlette / pytest-asyncio 产生了若干 `DeprecationWarning`，提示部分 asyncio API 将在 Python 3.16 移除。

### 解决方式

- 在 `pyproject.toml` 中将对应配置项设为 `function` 以解决问题。
- 当前阶段网站无图标，属于正常情况。
- 通过 `where python` 和 `where pytest` 确认真实虚拟环境位于项目根目录 `.venv/`。
- 后续在工具命令中使用 `.venv\Scripts\python.exe -m pytest backend`，避免依赖终端是否已激活虚拟环境。
- warning 当前不影响测试结果，后续可考虑使用 Python 3.11 / 3.12 作为项目开发版本，减少依赖兼容噪音。

### 学到的东西

- `pydantic-settings` 可以把 `.env` / 环境变量映射为 Python 配置对象。
- `get_settings()` 使用 `lru_cache` 后，多次调用会返回同一个配置实例，避免重复读取配置。
- Git Bash 自动激活虚拟环境依赖 shell 函数；新开的 CMD 会话不会继承这个状态。
- 用 `python -m pytest` 比直接执行 `pytest` 更稳定，因为它明确指定了使用哪个 Python 环境。
