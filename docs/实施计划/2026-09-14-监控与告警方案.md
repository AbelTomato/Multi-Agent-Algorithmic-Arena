# 监控与告警方案

## 当前目标

为单 ECS 灰度环境提供低依赖的运行检查，不引入 Prometheus、Grafana 或新的监控平台。检查失败时由 systemd service 返回非零状态并写入 journald；可选的 QQ 邮箱 SMTP 告警由独立包装器负责。

## 已实现文件

- `deploy/monitor/multi-agent-arena-monitor.sh`：运行检查脚本。
- `deploy/monitor/multi-agent-arena-monitor-alert.sh`：保留检查退出码并管理故障/恢复通知状态。
- `deploy/monitor/multi-agent-arena-monitor-mail.py`：使用 Python 标准库通过 SMTP SSL 发信。
- `deploy/monitor/multi-agent-arena-monitor.service`：systemd 一次性服务模板。
- `deploy/monitor/multi-agent-arena-monitor.timer`：启动后 2 分钟开始，此后每 5 分钟检查一次，随机延迟不超过 30 秒。

## 检查范围

脚本默认检查：

- `app-backend-1` 和 `app-postgres-1` 是否运行且为 Docker `healthy`；
- `http://127.0.0.1/health` 和 `http://127.0.0.1/api/problems` 是否返回成功响应；
- `/opt` 磁盘使用率是否低于 `80%`；
- 最新本地 PostgreSQL gzip 备份是否存在、未超过 `93600` 秒（26 小时）且 gzip 有效；
- 最近一次备份 systemd service 的 `Result` 是否为 `success`；
- backend 最近 `15m` 日志和 Nginx error log 最近 1000 行是否出现敏感字段模式；Nginx access log 仅检查疑似真实凭据值（长 Bearer 值、`api_key`/`secret`/`password`/`token` 参数长值或长 `sk-...`），不会因 `/secrets.json`、`/api_keys.json` 等普通扫描路径名误报。

检查失败只输出检查名称，不输出日志匹配内容、数据库内容、Prompt、API Key 或 Authorization。

## 邮件告警

邮件由独立包装器触发，使用 QQ 邮箱 SMTP SSL：`smtp.qq.com:465`。当前默认策略为：

- 正常变为故障：立即发送一封；
- 故障持续：每 `3600` 秒最多重复一封；
- 故障恢复：发送一封恢复通知；
- SMTP 未配置或发送失败：只写入 journald，不覆盖监控原始退出码。

邮件正文只包含主机短名、时间、状态和脱敏的检查名称。不会发送完整日志、数据库内容、Prompt、API Key、Authorization 或 Provider 响应。

QQ 邮箱配置文件 `/etc/multi-agent-arena/mail.env` 必须由用户通过受保护会话创建，权限为 `600`：

```env
SMTP_HOST=smtp.qq.com
SMTP_PORT=465
SMTP_USER=3218998135@qq.com
SMTP_PASSWORD=<QQ邮箱新生成的授权码>
ALERT_FROM=3218998135@qq.com
ALERT_TO=3218998135@qq.com
```

聊天中已经出现过的旧授权码不应继续使用；请在 QQ 邮箱后台撤销并重新生成授权码。新授权码不要发到聊天、命令行、Git 或日志中。

## ECS 配置示例

建议创建 `/etc/multi-agent-arena/monitor.env`，权限为 `600`：

```env
COMPOSE_FILE=/opt/multi-agent-arena/app/compose.yaml
BACKUP_DIR=/opt/multi-agent-arena/backups
BACKUP_SERVICE=multi-agent-arena-postgres-backup.service
BACKUP_MAX_AGE_SECONDS=93600
DISK_PATH=/opt
DISK_MAX_PERCENT=80
HTTP_TIMEOUT_SECONDS=10
LOG_WINDOW=15m
NGINX_ACCESS_LOG=/var/log/nginx/multi-agent-arena.access.log
NGINX_ERROR_LOG=/var/log/nginx/multi-agent-arena.error.log
```

## 安装命令

安装和启用会修改生产 ECS 的 `/usr/local/sbin`、`/usr/local/libexec`、`/etc/multi-agent-arena` 和 `/etc/systemd/system`，创建每 5 分钟执行的检查任务。以下命令已在目标 ECS `i-wz95igsjwjrfzpckjip5`（`cn-shenzhen`）执行；如果在其他环境执行，必须先核对实例和 Region：

```bash
sudo install -d -m 700 /etc/multi-agent-arena
sudo install -d -m 755 /usr/local/libexec
sudo install -m 750 deploy/monitor/multi-agent-arena-monitor.sh \
  /usr/local/sbin/multi-agent-arena-monitor
sudo install -m 750 deploy/monitor/multi-agent-arena-monitor-alert.sh \
  /usr/local/sbin/multi-agent-arena-monitor-alert
sudo install -m 755 deploy/monitor/multi-agent-arena-monitor-mail.py \
  /usr/local/libexec/multi-agent-arena-monitor-mail.py
sudo install -m 644 deploy/monitor/multi-agent-arena-monitor.service \
  /etc/systemd/system/multi-agent-arena-monitor.service
sudo install -m 644 deploy/monitor/multi-agent-arena-monitor.timer \
  /etc/systemd/system/multi-agent-arena-monitor.timer
sudo install -m 600 /path/to/reviewed/monitor.env /etc/multi-agent-arena/monitor.env
sudo systemctl daemon-reload
sudo systemctl enable --now multi-agent-arena-monitor.timer
sudo systemctl start multi-agent-arena-monitor.service
```

启用邮件前应另外创建 `/etc/multi-agent-arena/mail.env`，并确认 `SMTP_PASSWORD` 是新生成的 QQ 邮箱授权码。未创建该文件时，监控仍会正常检查，失败只记录 `alert_not_sent reason=mail_configuration_missing`。

## 验证与故障处理

```bash
sudo systemctl show multi-agent-arena-monitor.service \
  -p Result -p ExecMainStatus -p ActiveState --no-pager
sudo journalctl -u multi-agent-arena-monitor.service -n 50 --no-pager
sudo systemctl list-timers multi-agent-arena-monitor.timer --no-pager
```

检查 service 失败时，先读取脱敏的 `monitor_failed checks=...`，再分别检查 Docker、Nginx、磁盘、备份和日志。不要把完整日志直接发送到外部通知渠道。

停止监控任务：

```bash
sudo systemctl disable --now multi-agent-arena-monitor.timer
```

停止 timer 不会停止 backend、PostgreSQL、Nginx 或备份 timer。

## 告警渠道边界

QQ 邮箱告警代码和 systemd 接线已部署到目标 ECS。`/etc/multi-agent-arena/mail.env` 已由用户在 ECS 受保护会话中创建；Agent 仅核对到文件元数据，未读取其内容。systemd/journald 仍是监控结果的事实来源；邮件发送失败不会覆盖监控原始退出码。

部署后的只读验证结果：monitor service 的 `Result=success`、`ExecMainStatus=0`；timer 为 `enabled/active`；告警包装器、邮件脚本和 service 权限分别为 `750`、`755`、`644`；状态目录为 `700`。原有 `monitor.env` 和备份配置未被覆盖。
