# 阶段 D：账户主体、不可变提交与纯评测服务 Spec

**所属日期：** 2026-09-20
**冻结时间：** 2026-09-20 16:36（Asia/Shanghai，UTC+08:00）
**状态：** 已由用户确认；阶段 D 核心代码与隔离 SQLite 验证已完成。未执行持久化数据库 migration、seed、账户写入或生产升级；真实 Sandbox 集成和部分跨语言等价验收仍未完成。

## 1. 目标与非目标

### 1.1 目标

1. 引入人类与 Agent 两类独立账户主体。
2. 将候选源码固化为可审计、不可变的 `Submission`。
3. 评测只消费已有 Submission，不调用 Agent、Provider 或 CandidateGeneration。
4. 同时支持 Python 与 C++，由题目级语言白名单控制。
5. 移除旧匿名 `POST /api/evaluations` 入口，只保留 Submission/Evaluation API。
6. 旧匿名评测历史保留为不可重放摘要，不迁移伪装成新 Submission。

### 1.2 非目标

- 不实现自助注册、密码登录、OAuth、SSO、Token 自助管理。
- 不实现排名、提交次数上限、比赛轮次、截止时间、胜负或裁决规则。
- 不实现比赛状态机、异步评测队列、辩驳裁决或追问。
- 不允许调用方自由选择历史用例版本或以性能进行排名。

## 2. 账户、认证与题目权限

### 2.1 Account

每个账户是以下一种主体：

| 字段 | 规则 |
| --- | --- |
| `id` | 服务端生成的稳定 ID |
| `subject_type` | `human` 或 `agent`，创建后不可变 |
| `name` | 全局唯一，用于审计和展示 |
| `is_active` | 禁用后不能创建、读取或评测 Submission |
| `created_at` | 服务端记录的 UTC 时间 |

Agent 是独立账户主体，不能冒充或委托为人类账户。Submission 必须记录实际作者：`author_subject_type=agent`、`author_subject_id=<agent_id>`。

新 API 不接受客户端传入作者 ID；作者只能从 Bearer Token 的认证上下文解析。

### 2.2 Bearer Token

- 请求头使用 `Authorization: Bearer <token>`。
- 原始 Token 仅在受控 CLI/seed 签发时展示一次。
- 数据库只保存 Token 的 SHA-256 哈希、账户关联、撤销状态和创建时间。
- 无 Token、Token 无效、Token 已撤销或账户已禁用：返回 `401 Unauthorized`。
- Token 有效但没有题目权限，或访问其他主体的 Submission：返回 `403 Forbidden`。
- 阶段 D 不提供公开注册、登录、账户管理或 Token 管理 API。

### 2.3 题目权限

- 权限粒度为：账户 × 题目 × `submit`。
- 创建 Submission 和对该 Submission 创建 Evaluation，都要求当前账户拥有该题目的 `submit` 权限。
- 读取 Submission、读取其 Evaluation、创建修订，仅允许 Submission 作者本人。
- 账户、Token 和题目权限通过受控 CLI/seed 管理命令维护，不开放管理 API。

CLI/seed 会写持久化数据库。阶段 D 只在隔离临时数据库中验证这些命令；对本地持久库或生产环境执行账户创建、Token 签发、授权和 migration，必须另行获得明确批准。

## 3. Submission

### 3.1 不可变字段

创建后以下字段永远不可修改：

| 字段 | 规则 |
| --- | --- |
| `id` | 服务端生成 |
| `problem_id` | 关联题目 |
| `author_subject_id` | 从认证上下文写入 |
| `language` | `python` 或 `cpp` |
| `runtime_id` | 服务端由语言映射，不由客户端传入 |
| `source` | UTF-8 原始源码，最大 64 KiB |
| `source_sha256` | 服务端按原始 UTF-8 字节计算 |
| `created_at` | 服务端时间 |
| `supersedes_submission_id` | 可空；修订时指向同作者、同题目的旧版本 |
| `source_deleted_at` | 源码清理时写入 |
| `retention_expires_at` | `created_at + 90 天` |

不存在更新源码接口。修订必须创建全新的 Submission，旧 Submission、旧哈希和已有 Evaluation 均保持不变。允许同一旧版本产生多个修订分支，不引入“唯一最新版本”规则。

### 3.2 源码保留

- 原始源码默认保留 90 天。
- 到期清理任务删除 `source` 正文并写入 `source_deleted_at`。
- Submission 元数据、源码哈希、作者、版本链和 Evaluation 摘要继续保留。
- 源码清理后返回 `replayable=false`，标明“源码已清理，不可重放”。
- 源码清理后不得创建新的 Evaluation；哈希不能恢复源码。
- API 日志、评测响应和异常信息不得泄露隐藏用例、完整源码、编译命令或容器诊断。

## 4. 语言与题目准入

| API `language` | 服务端固定 `runtime_id` |
| --- | --- |
| `python` | `python-3.11-v1` |
| `cpp` | `cpp-gcc-14-cpp20-v1` |

- 每道题维护显式允许语言白名单。
- 客户端只提交 `language` 和 `source`，不能提交 `runtime_id`、镜像、编译参数、Docker 参数、资源限制或任务 ID。
- 题目不允许该语言时，拒绝创建 Submission，且不得产生持久化提交记录。
- Python 和 C++ 对同一题目使用相同 JSON I/O 协议和同一 Checker 语义。
- 阶段 D 验收同一题目的等价 Python/C++ 程序得到一致 AC/WA；不比较耗时，不做性能排名。

## 5. 服务边界

```text
CandidateGeneration
  └─ 仅生成结构化候选 {language, source}

SubmissionService
  └─ 认证与题目权限 → 校验语言/源码 → 写入不可变 Submission

EvaluationService
  └─ submission_id → 作者与题目权限校验 → 当前激活用例版本
     → Sandbox/Judge → 持久化 Evaluation 摘要
```

强制约束：

- CandidateGeneration 不得自行评测或写入 Evaluation。
- SubmissionService 不得隐式启动 Sandbox。
- EvaluationService 不得调用 Agent、Provider 或 CandidateGeneration。
- 所有新路径只能使用这一套 EvaluationService，不保留题目 ID 直接生成并评测的旁路。

## 6. API 语义

### 6.1 新 API

```http
POST /api/submissions
GET  /api/submissions/{submission_id}
POST /api/submissions/{submission_id}/evaluations
GET  /api/evaluations/{evaluation_id}
```

所有新接口都要求 Bearer Token。

### 6.2 创建 Submission

```json
{
  "problem_id": 1,
  "language": "cpp",
  "source": "#include <iostream>\nint main() { ... }",
  "supersedes_submission_id": null
}
```

创建只校验并持久化不可变版本，不触发评测。响应不必回显完整源码；作者读取详情时才可读取尚未过期的源码。

### 6.3 创建 Evaluation

- `POST /api/submissions/{submission_id}/evaluations` 同步执行。
- 成功时返回最终 `AC/WA/RE/TLE/MLE/OLE/UKE` 摘要，并持久化独立 Evaluation。
- 服务端自动使用题目当前激活的 `case_version`；客户端不得选择版本。
- Evaluation 固定记录 `submission_id`、执行时的 `source_sha256`、`language`、`runtime_id`、实际 `case_version`、状态、用例计数、摘要和时间字段。
- 同一 Submission 可多次评测，每次创建独立 Evaluation。
- 源码已清理时拒绝评测。
- Sandbox/Judge 不可用时返回受控错误，不生成伪造 AC/WA 记录。

### 6.4 旧入口

- 删除旧 `POST /api/evaluations`。
- 不保留匿名 Cookie 评测兼容层，不保留“题目 ID → Agent 生成 → 直接评测”旁路。
- 前端和所有调用方迁移到 Submission/Evaluation API。
- 既有匿名 `EvaluationRun` 只作为不可重放历史摘要保留，不补造 Submission、源码、作者账户、哈希或重放能力。

## 7. 数据库边界

阶段 D 计划新增或修改：

- `accounts`
- `access_tokens`
- `problem_submission_permissions`
- `submissions`
- `evaluations`
- 题目允许语言白名单

先生成并审查 migration 文件，再只在隔离临时数据库中验证升级/回滚。不得自动对本地持久库、共享库或生产库执行 migration、seed、账户创建、Token 签发或权限写入。

## 8. 验收标准

1. 人类和 Agent 使用同一 Submission API 创建各自提交。
2. 无认证、失效/撤销 Token、禁用账户返回 401。
3. 无题目 `submit` 权限、跨账户读取/修订/评测返回 403。
4. 语言不在题目白名单、源码为空/超过 64 KiB、非法修订关系被拒绝。
5. 提交创建后源码、语言、Runtime 和哈希不可变；修订产生新版本。
6. 源码哈希与原始 UTF-8 源码一致。
7. 创建 Submission 不调用 Sandbox、Judge、Agent 或 Provider。
8. 创建 Evaluation 不调用 Agent、Provider 或 CandidateGeneration。
9. Evaluation 固定绑定 Submission、哈希、Runtime 和当前激活 `case_version`。
10. Python/C++ 对同题等价程序使用相同 I/O 和 Checker，得到一致 AC/WA。
11. 源码满 90 天后清理：历史摘要可读、源码不可读、不可重新评测。
12. 旧 `POST /api/evaluations` 不存在；没有直接评测旁路。
13. migration 在隔离临时数据库完成升级和回滚验证。
