# 自动备份方案

## 目标

每天从生产 Compose 的 PostgreSQL 容器生成 gzip 压缩的逻辑备份，上传到杭州 OSS，并在上传后重新读取对象进行 SHA256 校验。

本方案不执行数据库 migration、restore、downgrade、seed 或卷操作。备份使用 PostgreSQL 的只读导出能力，不修改业务数据。

## 已实现文件

- `deploy/backup/multi-agent-arena-postgres-backup.sh`：备份、压缩、本地完整性检查、OSS 上传和远端 SHA256 校验。
- `deploy/backup/multi-agent-arena-postgres-backup.service`：systemd 一次性服务模板。
- `deploy/backup/multi-agent-arena-postgres-backup.timer`：每日 Asia/Shanghai `03:15` 执行，允许最多随机延迟 10 分钟。

## 运行逻辑

1. 使用 `docker compose exec -T postgres` 调用容器内的 `pg_dump`。
2. 通过 gzip 写入 `/opt/multi-agent-arena/backups` 下的临时文件。
3. 执行非空检查和 `gzip -t`。
4. 将临时文件原子移动为带时间戳的正式备份文件。
5. 设置备份目录权限为 `700`，备份文件权限为 `600`。
6. 使用 `ossutil --mode EcsRamRole` 上传到 `multi-agent-arena/postgres/` 前缀。
7. 从 OSS 读取刚上传的对象，仅计算 SHA256，不打印备份内容。
8. 本地和远端 SHA256 不一致时退出失败。

脚本不会自动删除本地历史备份。OSS 端沿用已配置的当前版本和非当前版本 7 天生命周期，避免在脚本中引入不可逆清理逻辑。

## 生产 ECS 配置示例

以下文件内容需要在 ECS 上由用户审查后创建，不能把真实凭据提交到仓库：

```env
COMPOSE_FILE=/opt/multi-agent-arena/app/compose.yaml
BACKUP_DIR=/opt/multi-agent-arena/backups
OSS_BUCKET_URI=oss://abeltomato-algorithmic-agent-arena-bucket/multi-agent-arena/postgres
OSS_REGION=cn-hangzhou
OSSUTIL_MODE=EcsRamRole
```

配置文件建议为 `/etc/multi-agent-arena/backup.env`，权限必须为 `600`。不应写入 AccessKey、Secret、STS Token 或数据库密码；数据库凭据由生产 Compose 环境传入 PostgreSQL 容器，OSS 认证由 ECS RAM Role 提供。

## 安装命令（待单独批准后执行）

安装和启用 systemd timer 会修改生产 ECS 的 `/usr/local/sbin`、`/etc/multi-agent-arena` 和 `/etc/systemd/system`，并创建每日自动任务。本仓库只提供模板，本轮未在 ECS 执行以下命令：

```bash
sudo install -d -m 700 /etc/multi-agent-arena
sudo install -m 750 deploy/backup/multi-agent-arena-postgres-backup.sh \
  /usr/local/sbin/multi-agent-arena-postgres-backup
sudo install -m 644 deploy/backup/multi-agent-arena-postgres-backup.service \
  /etc/systemd/system/multi-agent-arena-postgres-backup.service
sudo install -m 644 deploy/backup/multi-agent-arena-postgres-backup.timer \
  /etc/systemd/system/multi-agent-arena-postgres-backup.timer
sudo install -m 600 /path/to/reviewed/backup.env /etc/multi-agent-arena/backup.env
sudo systemctl daemon-reload
sudo systemctl enable --now multi-agent-arena-postgres-backup.timer
```

启用前应确认：ECS 实例、Region、RAM Role、Bucket 前缀、Compose 文件路径和维护窗口均正确。

## 首次验证

启用后建议先手动执行一次 service，随后只读取状态和日志：

```bash
sudo systemctl start multi-agent-arena-postgres-backup.service
sudo systemctl status --no-pager multi-agent-arena-postgres-backup.service
sudo journalctl -u multi-agent-arena-postgres-backup.service -n 50 --no-pager
sudo systemctl list-timers multi-agent-arena-postgres-backup.timer --no-pager
```

预期日志只包含对象 URI、大小和 SHA256，不包含数据库内容、密码、API Key 或 Authorization。随后应在隔离临时 PostgreSQL 中恢复最新 OSS 对象，并只读验证 Alembic 版本和 `problems` 数量。

## 失败处理与回滚

- `pg_dump`、gzip、OSS 上传或 SHA256 校验任一步失败，systemd service 以非零状态退出。
- 失败时保留已生成的本地正式文件，便于调查；脚本退出清理未完成的临时文件。
- 本方案不自动删除历史本地文件、不删除 OSS 对象、不修改数据库和不删除 Docker volume。
- 停止自动任务：

  ```bash
  sudo systemctl disable --now multi-agent-arena-postgres-backup.timer
  ```

- 停止 timer 不会删除已有备份或修改数据库；删除服务文件、配置文件或历史备份前需要另行确认。
