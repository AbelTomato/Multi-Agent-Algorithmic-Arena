### 2.2 已确认的 v1 业务 Spec

以下规则已由用户确认，或由用户明确授权执行者在已确认题意内定稿。后续业务测试以本节为准；改变题目合法域、状态含义、资源预算或公开 API 均须重新确认。

#### 2.2.1 首批题目及合法输入域

实现顺序为 Valid Parentheses、Two Sum。

**Valid Parentheses**

- 单例输入为 `{"s":"()[]{}"}`；`s` 必须是字符串，只包含 `()[]{}`。
- 空字符串合法，期望结果为 `true`。
- v1 不设置题目语义上的最大长度，也不加入长度边界用例；含其他字符的输入不纳入 v1 合法域。
- 执行请求仍须有安全字节上限。首版单例序列化输入上限为 64 KiB，此限制属于平台安全边界，不扩展题意。

**Two Sum**

- 单例输入为 `{"nums":[2,7,11,15],"target":9}`；`nums` 是至少含两个元素的 JSON 整数数组，`target` 是 JSON 整数。
- 数组元素和 `target` 范围为 `[-10^9, 10^9]`；JSON 布尔值不作为整数接受。
- 同一元素不能使用两次；v1 用例均恰有一个答案。无解、多解和超出整数范围的输入不纳入 v1 合法域。
- v1 不设置题意上的数组长度上限；单例序列化输入仍受 64 KiB 平台安全上限约束。

#### 2.2.2 语言无关的 JSON 标准输入输出协议

- 协议版本为 `json-stdio-v1`。候选代码是完整可执行程序，不采用 Python 固定函数签名。
- 每个用例使用独立任务容器；Judge 向 stdin 写入一个 JSON 对象，候选程序向 stdout 写入一个 JSON 对象后退出。
- stdout 只允许一个完整 JSON 文档及前后空白；额外非空白内容、空输出、非法 JSON、缺少字段、额外字段或字段类型错误均为 `RE`。
- stderr 可以使用，但与 stdout 合并计入输出预算；原始 stdout/stderr 不返回客户端、不写常规日志。
- Valid Parentheses 输出必须为 `{"result":true}`；Two Sum 输出必须为 `{"indices":[0,1]}`。
- 以后增加语言时只替换编译或启动适配器，复用输入输出、资源限制、生命周期和 Judge 协议；新增语言不属于 v1 实现范围。

#### 2.2.3 可信判定规则

- Valid Parentheses 对 `result` 做严格 JSON 布尔比较；`1`、`0` 和字符串不能替代布尔值。结构合法但布尔结果错误为 `WA`。
- Two Sum 的 `indices` 必须恰含两个严格 JSON 整数；两下标不同且均在数组范围内，满足 `nums[i] + nums[j] == target`。
- Two Sum 忽略下标顺序；JSON 布尔值不作为整数下标。结构合法但下标相同、越界或和不匹配为 `WA`，结构或类型错误为 `RE`。

#### 2.2.4 v1 用例及真值

用户已授权在上述合法域内构造首版用例。公开用例可以进入 Agent Prompt；隐藏用例及期望值只留在可信 Judge，不发送给 Provider、执行控制器、题目 API、评测 API或常规日志。执行器每次只能收到当前单例输入，不能收到期望值或完整用例集合。

**Valid Parentheses 公开用例**

| 输入 | 期望 |
| --- | --- |
| `{"s":""}` | `{"result":true}` |
| `{"s":"()"}` | `{"result":true}` |
| `{"s":"()[]{}"}` | `{"result":true}` |
| `{"s":"(]"}` | `{"result":false}` |
| `{"s":"([)]"}` | `{"result":false}` |
| `{"s":"{[]}"}` | `{"result":true}` |

**Valid Parentheses 隐藏用例**

| 输入 | 期望 | 覆盖意图 |
| --- | --- | --- |
| `{"s":"("}` | `{"result":false}` | 未闭合左括号 |
| `{"s":")"}` | `{"result":false}` | 无匹配左括号 |
| `{"s":"(((())))"}` | `{"result":true}` | 多层同类嵌套 |
| `{"s":"({[]})"}` | `{"result":true}` | 多类型正确嵌套 |
| `{"s":"(()]"}` | `{"result":false}` | 局部类型错误 |
| `{"s":"())"}` | `{"result":false}` | 提前闭合 |

**Two Sum 公开用例**

| 输入 | 合法下标集合 |
| --- | --- |
| `{"nums":[2,7,11,15],"target":9}` | `{0,1}` |
| `{"nums":[3,2,4],"target":6}` | `{1,2}` |
| `{"nums":[3,3],"target":6}` | `{0,1}` |

**Two Sum 隐藏用例**

| 输入 | 合法下标集合 | 覆盖意图 |
| --- | --- | --- |
| `{"nums":[-3,4,3,90],"target":0}` | `{0,2}` | 负数 |
| `{"nums":[0,4,3,0],"target":0}` | `{0,3}` | 两个零 |
| `{"nums":[1,2,3,4,8],"target":12}` | `{3,4}` | 答案位于后部 |
| `{"nums":[1,5,1,10],"target":2}` | `{0,2}` | 重复值、不同下标 |
| `{"nums":[-1000000000,1000000000],"target":0}` | `{0,1}` | 整数边界 |
| `{"nums":[-5,8],"target":3}` | `{0,1}` | 最小数组长度 |

#### 2.2.5 Agent 结构化生成结果

新评测链路要求 Agent 返回纯 JSON：

```json
{
  "language": "python",
  "code": "完整可执行 Python 程序",
  "explanation": "简短说明"
}
```

- `language` 必须严格为 `python`；`code` 必须是非空字符串；`explanation` 必须是字符串并允许为空；禁止额外字段和 Markdown 代码围栏。
- `code` 最大 64 KiB，`explanation` 最大 16 KiB，Agent 原始响应最大 128 KiB。
- 非法 JSON、缺失或额外字段、错误语言、空代码或长度超限均为 Agent 输出无效；不从 Markdown 中猜测或截取代码。
- 旧 `POST /api/solutions` 的 Markdown 契约保持不变。

#### 2.2.6 资源预算与评测方式

| 项目 | v1 限制 |
| --- | --- |
| CPU | 每任务 1 CPU |
| 内存 | 128 MiB；内存加 swap 总上限同为 128 MiB，不把 swap 作为额外预算 |
| PID | 32 |
| 临时空间 | 64 MiB |
| 单例输入 | 序列化后 64 KiB |
| 输出 | stdout 与 stderr 合计 64 KiB |
| 单用例墙钟 | 5 秒，包含容器与解释器启动及程序执行 |
| 单请求用例数 | 最多 32 |
| 本地并发 | 1；忙碌时拒绝，不做无界排队 |
| 总请求期限 | 210 秒，覆盖默认 30 秒 Agent 预算、最多 32 个用例及有界编排开销 |

- 首版串行逐用例执行，每用例独立任务容器；遇到首个失败即停止。
- 输出超过上限时立即终止任务并返回 `OLE`，不能等进程自然退出后才截断。
- 超时必须终止容器而不只是 Docker CLI 进程；取消路径同样必须清理自有容器。

#### 2.2.7 评测状态

| 状态 | 语义 |
| --- | --- |
| `AC` | 所有当前版本用例通过 |
| `WA` | 输出结构合法，但答案语义错误 |
| `RE` | 非零或信号退出，或 stdout 协议错误 |
| `TLE` | 单用例超过墙钟限制 |
| `MLE` | 有可靠 Docker/cgroup OOM 证据的内存超限 |
| `OLE` | stdout 与 stderr 合计超过输出限制 |
| `UKE` | 结果无法可靠分类，或 Judge/执行基础设施出现未知错误 |

- 仅凭退出码 137 不得判为 `MLE`；缺少可靠 OOM 证据时按实际证据归入 `RE` 或 `UKE`。
- Docker 不可用、控制器超时、用例文件损坏和协议版本不支持不得归为 `WA`；未执行或用例为空不得返回 `AC`。
- 摘要可以返回失败用例序号，但不得返回隐藏输入、期望答案、源码或原始输出。`AC` 仅表示通过当前 v1 用例。

#### 2.2.9 API 契约

新增 `POST /api/evaluations`，请求仅允许 `{"problem_id":1}`，额外字段禁止。完成评测时只返回摘要：

```json
{
  "problem_id": 1,
  "problem_slug": "valid-parentheses",
  "language": "python",
  "status": "AC",
  "case_version": "v1",
  "case_count": 12,
  "executed_count": 12,
  "passed_count": 12,
  "failed_case_index": null,
  "summary": "通过当前版本评测用例"

```

| HTTP | 场景 |
| --- | --- |
| `200` | 得到 `AC/WA/RE/TLE/MLE/OLE`；任务已执行但无法可靠分类时返回 `UKE` |
| `404` | 题目不存在 |
| `409` | 本地并发槽已占用 |
| `422` | 请求字段非法，或题目存在但没有配置用例 |
| `502` | Agent 调用失败或结构化输出无效 |
| `503` | 执行控制器不可连接或明确不可用 |
| `504` | 整个评测请求超过总期限 |

响应不得包含源码、Agent 原始响应、Prompt、Provider 内部错误、原始 stdout/stderr、隐藏输入或期望答案。保留原 `POST /api/solutions` 接口和 Markdown 行为。

### 2.3 语言边界与 Go 引入决策

#### 2.3.1 模块归属

| 模块 | 实现语言 | 本计划决策 |
| --- | --- | --- |
| FastAPI、Agent、Provider、数据库、EvaluationService | Python | 保持现有实现与测试边界 |
| 可信 Judge、用例目录 | Python | 修复并继续使用，不迁移 Go |
| 浏览器界面 | TypeScript/React | 保持现有技术栈 |
| 执行控制器 | Go | 阶段 1B 替换 Python 原型 |
| 候选程序运行时 | Python 3.11 | v1 唯一候选语言；Go 控制器不等于支持 Go 题解 |

#### 2.3.2 引入时机

- 在阶段 3 业务闭环之前完成 Go 控制器替换。原因是当前尚未实现的实时双流输出、统一取消、超时竞争、单槽准入、OOM 证据和标签化清理正是控制器核心职责；若先完整加固 Python 原型再迁移，会重复实现和重复验收。
- 不把 Go 推迟到阶段 4：阶段 4 负责更强隔离与稳定性加固，而阶段 3 已依赖可靠的执行生命周期。
- 不把 Go 扩大到业务后端或 Judge：现有 Python 业务边界成熟，重写不会直接提高沙箱隔离能力。

#### 2.3.3 迁移原则

1. 先冻结 `POST /execute`、`GET /health` 和执行结果字段，再替换内部实现。
2. Python 控制器仅作为历史原型和契约参考，不与 Go 控制器长期形成双正式实现。
3. Go 控制器通过标准库 `net/http`、`os/exec`、`context`、goroutine 和 channel 实现；初版继续调用固定 Docker CLI，不引入 Docker SDK。
4. Go 控制器通过服务端生成的任务 ID 和固定标签识别所有权；不得信任调用方提供的容器名，不得使用 `docker system prune` 或全局删除。
5. Go 控制器通过 loopback 提供内部服务；未重新设计网络边界前不得监听公网。
6. 旧 Python 控制器只有在 Go 控制器完成契约、单元和真实 Docker 验收后才能退役；删除旧文件属于破坏性操作，须另行取得具体许可。
7. Go 工具链版本、安装来源和构建方式尚未确认，不在本计划修订中假定已经可用。

## 3. 信任边界与执行模型

```text
浏览器 → FastAPI / EvaluationService
                 ├─ PostgreSQL：读取题目
                 ├─ Agent / Provider：仅收到题面、公开样例和代码协议
                 └─ 可信 Judge：持有用例、期望语义、聚合规则
                      ↓ 有界内部请求
                 独立 Go 执行控制器：固定镜像、固定限制、任务生命周期
                      ↓ Docker CLI（高权限可信边界）
                 一次性 Python 容器：代码 + 单个用例输入
                      ↓ 不可信输出
                 Judge 在容器外解析、比较、生成结果
```

- Web API 不持有 Docker Socket；任务容器也不持有。控制器即便独立部署，Docker 权限仍可能等同宿主机高权限，必须限制其入口和请求能力。
- 首个控制器建议为本机独立进程、仅绑定 loopback；如果 FastAPI 在容器中，须重新设计可达且受控的内部连接，不得直接扩大为公网监听。
- 控制器只接受代码、单例输入和受支持的协议版本；不接受客户端传入镜像、宿主机路径、挂载、任意命令或任意 Docker 参数。代码通过文件/标准输入传递，不拼接进 shell。
- 隐藏用例不送给 Provider，不由题目 API 返回；容器只能看到当前输入，不能看到期望答案和完整用例集合。不能保证当前输入对正在执行的代码“不可见”。
- 沙箱只禁网络并不足以防泄密：前端结果和日志不回显隐藏输入、原始 stdout/stderr、源码、Prompt 或凭据；可公开的诊断另行白名单定义。
- 禁止宿主机 `exec()` 模型代码；不在 FastAPI 容器内用普通 Python 子进程代替沙箱。

## 5. 验收矩阵与证据要求

| 验收项 | 测试层 | 必需证据 |
| --- | --- | --- |
| Go HTTP 协议 | Go 单元 + Python 契约 | 严格字段、字节边界、状态码和冻结契约兼容断言 |
| 执行与异常 | Go 单元 + 真实 Docker | 正常输出、非零退出、墙钟终止、取消和容器结束状态 |
| 输出预算 | Go 单元 + 真实 Docker | stdout/stderr 共享 64 KiB；达到上限立即终止而非退出后截断 |
| 所有权与清理 | Go 单元 + 真实 Docker | 服务端任务 ID、固定标签、只清理自有资源、无任务残留 |
| 内存与进程 | 真实 Docker | 实际 cgroup 限制和可靠 OOM 状态；不得仅凭退出码 137 推断 MLE |
| 网络与文件 | 真实 Docker | 本地受控目标不可达、非 root、根目录写失败、tmpfs 可写且有界 |
| 判题 | Python 单元 + 集成 | 已确认用例真值、版本、正确/错误答案和 Two Sum 输入语义 |
| 隐藏用例 | 单元 + 集成 | Provider 请求、执行输入和 API 输出均无隐藏期望值 |
| 故障语义 | 单元 + 集成 | Agent、候选运行和执行基础设施错误互不混淆 |
| 业务闭环 | API 集成 + 前端 | 固定 Agent 真实执行、状态展示、切题保护和旧接口回归 |

测试记录至少包含：环境、Go 版本、镜像摘要、协议/用例版本、具体命令、通过/失败/跳过数、跳过原因、容器清理结果及剩余风险。不得记录源码、隐藏输入、期望答案或原始执行输出。

**证据不可互换：** mock CLI 通过不等于 Docker 隔离通过；Docker 通过不等于算法业务验收通过；本地通过不等于 ECS、真实 Provider 或公网安全验收通过。

## 7. 交付、迁移、回填与停止条件

- 每个实现切片遵循“确认 Spec → 读取相关实现和测试 → 失败测试 → 最小实现 → 目标验证 → 范围内文档回填”。
- 本地评测功能缺省关闭；Go 控制器不可用时失败关闭，禁止降级为宿主机直接执行或旧 Python 正式入口。
- Go 迁移期间以 HTTP/JSON 契约为边界；不得同时扩展候选语言、重写 Judge 或改造无关业务模块。
- 旧 Python 控制器在 Go 验收前保留；验收后如需删除、移动或批量重命名，必须说明范围、影响和恢复方式并取得具体许可。
- 实际核心代码完成后列出完整绝对路径、重点接口、行为变化、风险和测试缺口；测试通过不等于业务正确或强安全验收完成。
- 阶段完成后按开发日志规范记录实际执行内容；纯计划修订默认不写开发日志。
- 不自动执行 Git 写操作，不运行无关全量测试，不修改生产 Compose、数据库、现有题目或历史部署日志。
- 遇到以下情况必须停止对应阶段并确认：Go 工具链来源未确认；需要安装软件或拉取构建镜像；Docker 临时资源范围未授权；HTTP 契约需要破坏性变更；安全限制无法生效；清理所有权不明确；需要新增依赖、外部费用、数据库写入或远程环境操作。
