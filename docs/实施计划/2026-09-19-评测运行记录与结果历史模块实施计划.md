**Goal:** 在不保存候选源码、Provider 原文、原始输入输出或隐藏用例的前提下，为现有同步评测链路增加可审计的运行记录、匿名会话历史和单次详情查询，并保持现有 Judge 结果及错误 HTTP 契约兼容。

**Architecture:** 保持 `POST /api/evaluations` 同步执行，由 FastAPI 生成高熵 HttpOnly 匿名会话 Cookie，只在 PostgreSQL 中保存其 SHA-256 哈希。评测服务在完成开关、题目和用例预检后先提交 `RUNNING` 记录，外部 Agent/Judge/Sandbox 调用期间不占用数据库事务，结束后再把 Judge 摘要或受控失败分类写回；读取接口始终按会话哈希隔离。第一阶段不引入用户系统、Redis、异步队列、SSE/WebSocket、排行榜或比赛状态机。

**Tech Stack:** Python 3.11+、FastAPI 0.115.6、Pydantic 2、SQLAlchemy Async 2、Alembic 1.14、PostgreSQL 16.4、pytest；React 19、TypeScript 5.9、Vite 7、Vitest 3。

**Spec:** 本计划兼作增量功能 Spec；基础约束来自 `/home/abeltomato/workspace/projects/Multi-Agent-Algorithmic-Arena/docs/MVP开发构想.md`、`/home/abeltomato/workspace/projects/Multi-Agent-Algorithmic-Arena/README.md` 和 `/home/abeltomato/workspace/projects/Multi-Agent-Algorithmic-Arena/docs/实施计划/2026-09-18-真实LLM与评测生产上线计划.md`。

## Global Constraints

- `POST /api/evaluations` 仍只接受 `{"problem_id": <positive int>}`，客户端不得提交 Prompt、模型、Provider、候选代码、用例、资源限制或会话 ID。
- 现有成功响应的 Judge 字段名称和含义保持不变；只允许添加 `evaluation_id`、`run_status`、`created_at`、`finished_at` 和 `duration_ms`。
- `AC/WA/RE/TLE/MLE/OLE/UKE` 是 Judge 结果；`RUNNING/SUCCEEDED/FAILED/TIMED_OUT/REJECTED/INTERRUPTED` 是运行生命周期，两者不得混用。
- Judge 正常产出任何结果（包括 `WA/RE/TLE/MLE/OLE/UKE`）时，运行状态均为 `SUCCEEDED`；只有编排、Provider、Controller 或持久化链路失败才使用非成功运行状态。
- 评测关闭、题目不存在、用例未配置或请求体非法时不创建运行记录，因为这些请求尚未进入可执行评测。
- Controller 忙对应 `REJECTED`；Controller 或总期限超时对应 `TIMED_OUT`；Agent、Controller 不可用/协议错误及其他受控编排失败对应 `FAILED`；服务进程重启后遗留的过期 `RUNNING` 记录由恢复逻辑标记为 `INTERRUPTED`。
- 数据库及 API 均不得保存或返回候选源码、完整 Prompt、Provider 原始响应/API Key、stdin、stdout、stderr、隐藏用例、容器 ID、Controller task ID 或内部异常文本。
- 匿名会话 Cookie 使用 32 字节以上加密随机值，`HttpOnly`、`SameSite=Lax`、路径限定为 `/api/evaluations`；数据库只保存十六进制 SHA-256 哈希。Cookie 被窃取即等同匿名历史访问权，因此响应和日志不得输出 Cookie 值。
- 匿名历史保留期默认为 30 天；列表和详情不暴露过期记录。物理清理由默认 dry-run 的维护命令完成，任何持久化数据库上的实际删除都属于需单独批准的数据库写操作。
- 历史列表默认 `limit=20`，最大 `50`，`offset>=0`，按 `created_at DESC, id DESC` 排序；可选 `problem_id` 过滤只能接受正整数。
- 历史详情对不存在、过期或不属于当前匿名会话的 ID 统一返回 `404`，不得泄露记录是否真实存在。
- 本地开发与生产前端必须通过同源入口或 Vite 代理访问 API；本阶段不为跨站 Cookie 放宽 CORS 或启用 `allow_credentials=True`。
- 真实评测集成测试会创建和删除 Arena 标签临时容器，必须另行获得具体授权；普通计划执行默认只运行 fake/SQLite 隔离测试。
- Git 提交不是自动步骤；如需执行 `git add`/`git commit`，必须根据项目规则另行取得明确批准。

## 当前基线与优先级判断

### 已具备能力

- FastAPI 已提供题目、Markdown 解法和同步评测接口。
- OpenAI Compatible Provider、可信 Judge、Go Controller 和受限临时候选容器已形成真实链路。
- ECS 已具备 HTTPS、Nginx 限流、Controller 审计、监控、备份和人工关闭评测路径。
- 前端可展示当前请求的 Judge 摘要，但刷新后结果丢失。

### 当前缺口

- 后端不持久化评测运行，无法回答“何时运行、结果是什么、失败在哪一层”。
- 没有可供后续评分、排行榜或比赛状态机复用的稳定评测事实表。
- Controller JSONL 审计聚焦执行参数与清理，不应承担产品历史查询。
- 当前匿名且无登录，因此需要先建立最小、不可枚举、同源的历史隔离边界。

### 为什么不直接实现排行榜或比赛

排行榜需要明确用户身份、分数计算、重复提交去重、题目权重和并列规则；比赛还需要报名、时间窗、状态机和反作弊。当前缺少这些业务 Spec。评测运行记录是二者共同依赖且可独立验收的最小数据基础，因此本计划只交付历史模块，不自行创造积分或比赛规则。

## 固定数据契约

### ORM 字段

`EvaluationRun` 使用以下字段；实现时不得任意增加敏感列：

```python
class EvaluationRunStatus(StrEnum):
    RUNNING = "RUNNING"
    SUCCEEDED = "SUCCEEDED"
    FAILED = "FAILED"
    TIMED_OUT = "TIMED_OUT"
    REJECTED = "REJECTED"
    INTERRUPTED = "INTERRUPTED"


class EvaluationErrorCategory(StrEnum):
    AGENT_ERROR = "AGENT_ERROR"
    CONTROLLER_BUSY = "CONTROLLER_BUSY"
    CONTROLLER_UNAVAILABLE = "CONTROLLER_UNAVAILABLE"
    CONTROLLER_TIMEOUT = "CONTROLLER_TIMEOUT"
    CONTROLLER_RESPONSE_ERROR = "CONTROLLER_RESPONSE_ERROR"
    EVALUATION_TIMEOUT = "EVALUATION_TIMEOUT"
    INTERNAL_ERROR = "INTERNAL_ERROR"


class EvaluationRun(Base):
    __tablename__ = "evaluation_runs"

    id: Mapped[UUID]
    session_key_hash: Mapped[str]       # 64 个十六进制字符
    problem_id: Mapped[int]             # FK problems.id，RESTRICT 删除
    problem_slug: Mapped[str]           # 结果快照
    language: Mapped[str]               # 固定 python
    run_status: Mapped[str]
    judge_status: Mapped[str | None]
    case_version: Mapped[str]
    case_count: Mapped[int]
    executed_count: Mapped[int | None]
    passed_count: Mapped[int | None]
    failed_case_index: Mapped[int | None]
    summary: Mapped[str | None]         # 受控摘要，不写内部异常
    error_category: Mapped[str | None]
    created_at: Mapped[datetime]
    started_at: Mapped[datetime]
    finished_at: Mapped[datetime | None]
    duration_ms: Mapped[int | None]
```

约束：

- 主键使用应用端 `uuid.uuid4()` 与 SQLAlchemy `Uuid(as_uuid=True)`，兼容 PostgreSQL 和 SQLite 测试。
- `session_key_hash` 建普通索引；列表使用复合索引 `(session_key_hash, created_at, id)`；题目过滤使用 `(session_key_hash, problem_id, created_at, id)`。
- `run_status`、`judge_status` 和 `error_category` 使用字符串列加 Check Constraint，避免 PostgreSQL enum 的后续迁移负担。
- `case_count/executed_count/passed_count/duration_ms >= 0`；`failed_case_index` 为空或 `>=0`。
- `SUCCEEDED` 必须有 `judge_status`、所有计数字段、`summary`、`finished_at` 和 `duration_ms`，且 `error_category IS NULL`。
- 其他终态必须有 `error_category`、安全 `summary`、`finished_at` 和 `duration_ms`，且 `judge_status IS NULL`。
- `RUNNING` 不得有 Judge 结果、错误分类、结束时间或耗时。

class EvaluationRunListResponse(BaseModel):

## 已知风险、假设和未覆盖场景

1. **匿名 Cookie 不是账户身份。** 清 Cookie、换浏览器或换设备后无法恢复历史；Cookie 被窃取后可读取该匿名历史。完整用户历史必须等待登录/账户 Spec。
2. **同步请求仍受现有限时约束。** 本模块不提供后台任务、轮询、断点续传或请求完成通知。
3. **先写 RUNNING 再外部执行存在中断窗口。** 进程崩溃时依赖 stale 恢复标记 `INTERRUPTED`，不能精确还原崩溃前最后一步。
4. **数据库写失败时不能保证历史完整。** 为避免返回“已记录”的假成功，终态写入失败时请求必须失败关闭；已经发生的 Provider 或 Sandbox 成本无法回滚。
5. **保留期清理不是自动部署。** 代码只提供安全 dry-run/execute 命令；是否配置 systemd timer、执行频率和生产首次删除需另立运维审批。
6. **没有评分和去重规则。** 同题多次运行全部作为独立事实保存，不计算最好成绩、积分或排名。
7. **不保存调试原文。** 产品历史只能显示受控分类和摘要；底层排障继续依赖既有脱敏服务日志和 Controller 审计。
8. **容量估算待真实数据验证。** 首版使用 offset 分页，适合单用户低流量；数据量明显增长后再依据查询计划决定 cursor 分页或归档，不提前引入复杂方案。
