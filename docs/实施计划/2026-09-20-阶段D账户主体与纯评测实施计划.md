**目标：** 在不保留匿名新评测入口的前提下，引入账户主体、不可变 Submission、Python/C++ 题目语言准入和只消费 Submission 的同步 Evaluation 服务。

**架构：** FastAPI 认证依赖解析 Bearer Token 为当前账户主体；SubmissionService 负责主体授权、源码校验、哈希和不可变版本；EvaluationService 只消费已持久化 Submission 与题目当前用例版本，调用现有 Judge，不接触 Agent/Provider。旧匿名 EvaluationRun 仅保留只读历史摘要语义。

**技术栈：** 现有 FastAPI、Pydantic、SQLAlchemy Async、Alembic、PostgreSQL/SQLite 临时测试库、httpx、pytest；不引入新依赖、消息中间件或新的运行时。

## 全局约束

- 账户主体只有 `human` 和 `agent`；Agent 是独立作者，不冒充人类。
- 认证使用 `Authorization: Bearer <token>`；数据库只保存 Token SHA-256 哈希。
- 不提供公开注册、登录、账户管理或 Token 管理 API；账户和权限仅由受控 CLI/seed 维护。
- Submission 创建后不可更新；修订必须新建 Submission 并记录 `supersedes_submission_id`。
- 源码最大 64 KiB UTF-8，默认保留 90 天；清理后历史不可重放。
- `python` 固定映射 `python-3.11-v1`；`cpp` 固定映射 `cpp-gcc-14-cpp20-v1`。
- 题目必须有显式语言白名单；客户端不得传入 Runtime、镜像、命令、挂载或资源限制。
- Evaluation 使用题目当前激活用例版本，客户端不能选择 `case_version`。
- EvaluationService 不调用 Agent、Provider 或 CandidateGeneration。
- 移除旧 `POST /api/evaluations`；匿名历史不伪装成新 Submission。
- 只在隔离临时 SQLite 数据库执行自动化迁移验证；不执行持久数据库 migration/seed/写入。
- 不运行真实模型请求、生产部署、镜像拉取或真实 Docker 集成测试，除非另行批准。
