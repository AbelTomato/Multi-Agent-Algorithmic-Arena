# MVP 全链路收口实施计划

## 1. 目标

在不扩展 Judge0、代码执行、比赛、Redis、WebSocket、登录、历史记录和多 Provider 路由等非 MVP 能力的前提下，完成单 Agent 算法题解答 MVP 的可验证闭环：

```text
React 前端
→ Nginx 正式域名 HTTPS 入口（公网 IP 灰度回退）
→ FastAPI
→ PostgreSQL / OpenAI Compatible Provider
→ 一次性 Markdown 解题结果
```

公网 IP 灰度环境仍作为受限回退入口保留；`tomato-agent-arena.me` 已完成备案、DNS、证书和 HTTPS 切换，并于 2026-09-18 通过线上验收。

## 3. 范围和约束

### 3.1 本计划包含

- Provider 运行环境隔离和错误脱敏测试；
- 前端灰度状态与 HTTP `429` 限流提示；
- 公网 IP Nginx 灰度模板和 `/api/solutions` 限流；
- ECS 安全组来源限制、端口隔离和基础健康检查；
- 专用 API Key 的轮换、额度、告警和一次受控真实请求；
- 备份完整性、异地保存和隔离恢复演练；
- 应用级回滚路径；
- 条件式正式域名 HTTPS 切换；
- 测试、文档回填和最终验收。

### 3.2 本计划不包含

- Judge0 或任何代码执行沙箱；
- 正确性评测、评分、排行榜、比赛状态机、多 Agent、辩驳；
- WebSocket、SSE、流式输出、Redis、异步队列；
- 登录、注册、OAuth、用户历史、题库后台、外部题库导入；
- 多 Provider 路由、自动回退或业务层访问控制。

### 3.3 全局约束

- 前端只能发送 `{ "problem_id": number }`，不得发送或控制 Prompt、Provider、模型、最大 Token、温度或重试次数。
- 默认配置保持 `LLM_PROVIDER=mock`；真实 Provider 仅在 ECS backend 运行环境中启用。
- 生产环境必须保持 `DEBUG=false`、`CORS_ORIGINS` 不使用 `*`、PostgreSQL 不开放公网端口、backend 只绑定 `127.0.0.1:8000`。
- API Key、数据库密码、Authorization、Prompt、完整模型输出和完整上游响应不得出现在 Git、前端、镜像、命令历史、开发日志或工具输出中。
- 现有工作区已存在未提交文档改动；实施过程不得覆盖、删除或回滚这些改动。

## 4. 高危操作审批门

下列操作必须在执行前取得针对具体目标、范围、影响和恢复方式的明确批准：

| 操作 | 目标 | 恢复边界 |
| --- | --- | --- |
| 修改 ECS 安全组、防火墙、Nginx 或公网入口 | ECS `47.119.120.86` | 保留 SSH 恢复规则和 Nginx 配置备份 |
| 写入、轮换或撤销 API Key / 数据库密码 | Provider 控制台和 ECS `.env.deploy` | 保留旧 Key 状态记录；不输出密钥内容 |
| 重建或重启生产 backend | ECS Docker Compose 服务 | 保留旧镜像、旧运行时配置和健康检查路径 |
| 数据库备份、migration、seed、restore | ECS PostgreSQL | 先备份；restore 仅允许隔离临时目标，禁止覆盖生产 volume |
| 上传到异地备份存储 | 经批准的受保护存储 | 校验和、加密、保留期和访问范围必须明确 |
| Certbot、TLS、正式域名切换 | `tomato-agent-arena.me` | 保留公网 IP 灰度配置作为回退 |
| Git add/commit/push | 本仓库和 `origin/main` | 先审阅 diff，分离既有改动和本次改动 |

一般性的“继续”“完成它”不构成上述操作的批准。

```text
本地 backend 与 frontend 测试、编译、构建通过

ECS 安全组仅允许批准来源访问灰度 HTTP
PostgreSQL 5432 与 backend 8000 无公网直连
Nginx /api/solutions 限流实际返回 429

文档与开发日志的当前状态一致
```
